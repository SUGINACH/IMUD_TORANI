# בדיקות קבלה / Acceptance tests

שתי שכבות בדיקות. **כל שינוי בקוד חייב לעבור את שתיהן לפני שהוא מתקבל.**

```bash
npm install && npx playwright install chromium     # פעם אחת
npm run test:layout:quick     # ~1 דקה: 7 תרחישים מייצגים
npm run test:layout           # ~2.5 דקות: כל 21 התרחישים
npm run test:features         # בדיקות פיצ'רים (טעינה, ייצוא, ייבוא הגדרות...)
```

## 1. בדיקת גיאומטריית עימוד (`tests/layout`)
מעמד את כל תרחיש בכרום headless ומריץ את `check_layout.js` על התוצאה:
גלישה אל אזור ההערות/מספר העמוד, אי-יישור תחתיות הטורים, כותרת יתומה בסוף טור, שורה בודדת (אלמנה/יתומה),
חלקי פסקה שנחתכו לא נכון, וטקסט שאבד או השתנה.

התרחישים (`scenarios.js`): קטע הספר האמיתי (`doc`), "פרקים בעייתיים" (`prob`), 9 תצורות טיפוגרפיות (`cfg-*`: גודל גופן,
גובה שורה, עמודות הערות, כותרות inline, רוחב עמודה), ו-10 מסמכים אקראיים דטרמיניסטיים (`synth-*`) עם כותרות מכל הרמות, הערות צד והערות שוליים.

`baseline.json` מחזיק את התוצאות המקובלות. הריצה נכשלת (exit 1) אם **סוג חריגה כלשהו גדל** בתרחיש כלשהו, או אם נוספו שגיאות JavaScript.
שיפור לא נכשל, ומדווח. אחרי שיפור מאושר: `npm run baseline:update`.

> ההשוואה תקפה רק עם תיקיית `fonts/` האמיתית (`tools/import-from-old-repo.sh`). בלעדיה הריצה מזהירה ואינה נכשלת.

## 2. בדיקות פיצ'רים (`tests/features`)
קבצי `*.test.js`, כל פיצ'ר שהועבר מגרסה אחרת מקבל בדיקה משלו (נוסף יחד עם ההעברה).

## הערות
- `layout/check_layout.js` נכתב במקור בסשן של V20.1 (IMUD_TORANI). הוא מודד גיאומטריה בלבד, לא אסתטיקה: אחרי שינוי מנוע יש גם להסתכל על עמודים.
- התלות בשמות מחלקות (`.block-2col`, `.right-col`, `.left-col`, `.footnote-area`, `.page-number-footer`, `data-token-id` ...) מכוונת: שינוי שמות כאלה חייב להתעדכן בבודק.
