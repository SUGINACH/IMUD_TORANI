# כללי עבודה — כדי שלא יאבדו תיקונים

הענפים הקודמים התפצלו, ובכמה מקרים העלאה של קבצים מ"שיחה" אחרת **דרסה** קבצים מרכזיים וגרפה אחורה תיקונים
(למשל: קו V21 עם ~90 קומיטים נעלם מקצה V20.1 ו-V20.2 בהעלאה אחת). הכללים הבאים נועדו לחסום את זה.

## 1. ענף ראשי אחד
`main` הוא מקור האמת. כל סשן (אדם או AI) עובד על ענף שנפתח מ-`main` העדכני ביותר, ומחזיר **diff**, לא קבצים שלמים.

## 2. קובץ שהגיע מבחוץ
1. לא מעתיקים אותו מעל הקובץ בריפו.
2. מריצים `git diff --no-index <קובץ-בריפו> <קובץ-חיצוני>` ורואים מה באמת השתנה.
3. כל hunk נבחן לחוד: האם זה תיקון? האם הקובץ החיצוני חסר משהו שקיים אצלנו (סימן לגרסה ישנה)?
4. ממזגים רק את מה שנועד; מריצים בדיקות.

## 3. שער איכות (חובה לפני קבלה)
```bash
npm run test:layout:quick && npm run test:features    # בכל קומיט
npm run test:layout                                   # לפני סיום משימה
```
- `tests/layout/baseline.json` = התוצאות המקובלות. סוג חריגה שעולה בתרחיש כלשהו = כישלון.
- מעדכנים baseline (`npm run baseline:update`) **רק** אחרי שיפור מאושר או שינוי מכוון של ברירות מחדל, ומסבירים בהודעת הקומיט.
- בודק הגיאומטריה אינו בודק אסתטיקה: אחרי שינוי מנוע יש גם להסתכל על עמודים (צילומי מסך).

## 4. פיצ'ר חדש / מועבר
- בדיקה ב-`tests/features/NN-name.test.js` שמוכיחה שהפיצ'ר עובד (ושנכשלת בלעדיו).
- שורה ב-`docs/FEATURE_MAP.md`: מקור (ענף/קומיט/קובץ), סטטוס, הערות.
- קומיט נפרד לכל פיצ'ר; הודעת הקומיט מציינת מקור ותוצאת הבדיקות.

## 5. מה לא עושים
- לא מוחקים `archive/` או `docs/knowledge/` (שם נמצאות הגישות האחרות ויומני הכשלונות).
- לא מניחים שהקובץ בגרסה אחרת "חדש יותר" לפי מספר הגרסה: מספרי V20.x אינם מסמנים התקדמות.
- לא מטילים ספק בבדיקות כדי לעבור אותן: אם בדיקה נכשלת — מחקרים את הסיבה.
- נוגעים במנוע (`typesetter.js`) רק עם הרצת הסוויטה המלאה; שמות מחלקות ש-`check_layout.js` תלוי בהם
  (`.block-2col`, `.right-col`, `.left-col`, `.footnote-area`, `.page-number-footer`) לא משתנים בלי עדכון הבודק.

## 6. סביבה
נדרש Node + Playwright (`npm install && npx playwright install chromium`) ותיקיית `fonts/` (`tools/import-from-old-repo.sh`).
בסביבה בלי דפדפן אמיתי אי אפשר לאמת עימוד — צריך לומר זאת במפורש ולא לטעון לתיקון מאומת.
